The coding practices every project in the family is held to. They are the five [composition invariants](/composition/#the-five-invariants) turned into day-to-day rules: how a class is laid out, where a counter lives, what a test must prove before a change lands.

Pages will be added here one rule at a time. Planned topics:

- Composition over inheritance: one type per file, one wiring file per program.
- Designing by interface in C++20: concepts for static contracts, abstract classes for runtime choices.
- Bounded everything: sizing pools and queues, and returning overload instead of absorbing it.
- One contract, two compilers: sharing headers between eBPF and C++.
- The ledger: measuring the cost of every network function.
